## 현장에서 사용하는 순서

1. iPhone Safari에서 사이트를 엽니다.
2. 도서관 [공식 소장자료 검색](https://postech.primo.exlibrisgroup.com/discovery/search?vid=82POSTECH_INST:82POSTECH&lang=ko&tab=LibraryCatalog&search_scope=MyInstitution)으로 실물 도서의 제목, 청구기호, 소장 위치가 3층 단행본인지 확인합니다.
3. 앱에 준비된 두 책의 실제 서가 위치를 현장에서 확인한 뒤 공식 3층 도면에 찍습니다.
4. 카트에서 이번에 찾을 책만 체크하고, 현재 위치를 도면에 찍습니다.
5. 눈앞에 보이는 기준 지점을 도면에 표시합니다. 그 지점을 향해 iPhone 윗부분을 겨눈 채 방향 보정 버튼을 누르고 동작 및 방향 권한을 허용합니다.
6. 방향을 맞춘 출발 지점에서 ④ 걷기 보정을 시작합니다. 선택한 기준 지점까지 곧게 걸어간 뒤 ④를 다시 눌러 감지된 걸음 수와 도면상 거리를 보정합니다.
7. 지도의 파란 점과 목표 서가 방향 안내를 보며 이동합니다. 아이폰을 걷는 방향으로 향하게 들면 감지된 걸음마다 추정 위치가 갱신됩니다. 서가 표지에서 파란 점을 다시 찍으면 누적 오차를 줄일 수 있습니다.
8. 서가에 도착하면 카메라를 열고 책등의 글자를 인식합니다. 찾음/못 찾음을 직접 기록하고 다음 책으로 이동합니다.

## 검증 범위와 제한

- 실제 도서 목록과 대출 상태를 실시간으로 가져오지 않습니다. 공식 검색 결과를 현장에서 확인해야 합니다.
- 공개 배치도에는 서가 줄과 구역 번호가 있지만 개별 청구기호가 어느 줄에 있는지는 없습니다. 책 위치를 현장에서 확인하지 않은 상태에서는 경로 시작이 차단됩니다.
- 방문 순서는 사용자가 찍은 점 사이의 화면상 거리를 기준으로 합니다. 통로 길이 기준 최적 경로는 아닙니다.
- 지도 아래 방향 문구는 사용자가 보정한 아이폰 나침반 값과 도면에서 찍은 현재 위치 및 서가 위치를 사용합니다. 걸음 센서로 지도 위치를 자동 추정합니다.
- 걸음 추정에는 초기 직선 보정 구간이 필요합니다. 센서 오검출, 휴대폰을 든 방향 변화, 회전, 보폭 변화 때문에 오차가 누적됩니다. 12걸음 이상 재확인하지 않으면 앱이 위치 확인을 권합니다. 실제 도서관에서 수치 정확도는 아직 측정하지 않았습니다.
- 지도선과 방향 문구는 목표 서가의 직선 방향입니다. 벽이나 서가를 피한 보행 경로가 아닙니다. 실제 통로 지점은 현장 답사를 통해 입력해야 합니다.
- OCR은 현재 프레임의 글자를 읽는 실험 기능입니다. 정확도는 조명, 책등 크기, 글꼴, 기기 성능에 따라 달라집니다. 인식 결과만으로 책을 찾았다고 기록하지 않습니다.
- 현장 방문, 실물 소장 상태, iPhone Safari 카메라 동작은 아직 확인하지 못했습니다. 실제 참가자 UT 전 운영자가 사전 답사와 기기 점검을 해야 합니다.

이 빌드는 이동 중 AR 카메라를 제거한 지도 중심 UT 버전입니다. 책등 확인 단계의 카메라 OCR은 유지합니다. 사용자 흐름과 현장 수집을 위한 버전입니다. 자동 실내 길 안내의 성능 검증 자료로 사용하면 안 됩니다.
